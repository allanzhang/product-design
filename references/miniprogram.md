# 微信小程序专项（B 端/内部工具型）

小程序不是"缩小的 Web"。平台约束是硬性的，违反会导致审核驳回或手势冲突。

## 1. 尺寸与布局

- 设计基准宽 **750rpx**；所有尺寸用 rpx（2 倍稿 1px = 1rpx）。文字最小 22rpx，正文 28–32rpx。
- **触控目标 ≥ 88rpx × 88rpx**（约 44pt），相邻可点元素间距 ≥ 16rpx。
- 安全区：顶部适配自定义导航栏，底部用 `env(safe-area-inset-bottom)` 或 `wx.getSystemInfoSync()` 的 safeArea 给底部按钮栏留高（iPhone 底部约 34pt）。

## 2. 导航与微信胶囊（硬约束）

- 右上角胶囊按钮（关闭/更多）区域不可遮挡：自定义导航栏时用 `wx.getMenuButtonBoundingClientRect()` 拿胶囊位置，导航内容垂直居中对齐胶囊、右侧留出胶囊宽度 + 边距。
- 自定义导航栏高度 = 状态栏高度 + 胶囊高度 + 上下间距；页面标题放在该区域内。
- 一级页面 ≤ 5 个用原生 `tabBar`（配置在 app.json，图标需本地资源，选中态用 `--primary`）；深层页面用顶部导航返回。
- 页面层级最多 10 层；流程设计避免过深跳转，下单/审批这类线性流程控制在 5 层内。

## 3. 优先使用原生能力

- 能用原生组件就不自绘：`button`（含 open-type 能力：获取手机号、授权、客服）、`input`/`textarea`、`picker`/`picker-view`（选择器别自己做弹层）、`switch`、`slider`、`checkbox/radio`、`scroll-view`、`swiper`（轮播）、`modal/popup` 用原生交互或标准半屏弹层。
- 反馈用原生 API：轻提示 `wx.showToast`（success/error/loading 自带图标）、进行中 `wx.showLoading`、确认对话框 `wx.showModal`（破坏性操作用它做二次确认）、长列表项操作 `wx.showActionSheet`。
- 不要在小程序里仿造 Web hover 效果；可点元素用 `hover-class` 做按压态（背景变 `--surface-2`）。

## 4. B 端高频页面模式

- **列表页**：顶部搜索框（吸顶）+ 横向筛选标签（状态分段控制器用原生分段样式或 tab）+ 卡片列表。每条目卡片：标题行（名称 + 状态色点文字）、关键信息 2–3 行（订单号/SKU 用等宽）、右侧金额或主操作。卡片间距 24rpx，卡片内边距 32rpx，卡片间距即分组，不要卡中卡。
- **详情页**：顶部状态区（大标题 + 状态 + 主操作按钮吸底），信息分区用**分隔线 + 小标题**，不用整屏卡片堆叠；明细用列表行而非表格（宽表格在手机上不可用，超过 3 列改为"卡片行 + 右对齐数值"）。
- **表单/下单**：label 左、控件右的行式表单（cell 表单），每行高 ≥ 96rpx；必填 `*`；错误红字在该行下方；金额合计固定吸底栏（"合计 ¥1,280.00"+ 提交按钮，底部留安全区）。
- **审批/待办**：卡片列表按状态分 tab（待我处理/已处理）；卡片内直接放同意/驳回按钮，驳回必须弹 modal 填理由。

## 5. 反馈与状态

- 首屏加载：骨架屏（灰色块 pulse）或 `wx.showLoading`；下拉刷新用 `enablePullDownRefresh` 原生样式。
- 空状态：插画（单色线性、克制）+ 一句话 + 主操作按钮，居中偏上。
- 列表分页：触底加载（`onReachBottom`），加载中/没有更多用文字分隔行；不用"点击加载更多"按钮。
- 网络失败：页面级错误态 + 重试按钮；表单提交失败保留用户输入，不清空。

## 6. 视觉约束（比 Web 更严）

- 颜色规则与 visual-system.md 一致：中性地基 + 语义色；小程序里**尤其**要避免彩色大爆炸——小屏上颜色噪声更致命。
- 图片：商品图是主要视觉来源，用正方形/4:3 圆角图，懒加载（`lazy-load`）；图标用单色线性图标，禁止彩色图标方块。
- 字体：只用系统字体栈；数字等宽；不加载外部字体文件（包体积 2MB 主包限制）。
- 不做：视差、bounce 动画、自动轮播营销、装饰渐变。动效只用 `wx.nextTick` 后的状态过渡（如勾选成功、吸底栏出现），并尊重 `wx.getSystemInfo` 的 reduced-motion 倾向。

## 7. 性能即体验

- `setData` 批量合并、只传变化字段；长列表数据分片，避免一次 setData 超 256KB。
- 主包 ≤ 2MB，整包 ≤ 20MB；重页面用分包；图片走 CDN 压缩。
- 商品图片用 webp/压缩图，缩略图与详情图分开尺寸。
